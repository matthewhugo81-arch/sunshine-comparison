Cloud amounts and sunshine — total, low, medium and high

Every model supplies its own cloud fields from the same run and sampled grid cell as its sunshine estimate. These are sunrise-to-sunset time-weighted cloud percentages, not 24-hour averages. Hourly cloud endpoints are linearly interpolated over the daylight portion of each interval. This does not recover unresolved sub-hourly cloud changes.

Provider total cloud is retained separately: overlapping low, medium and high layers are not added together. Layer definitions can differ between models. High cloud is not automatically opaque; cloud fraction alone does not describe optical thickness. Cloud amounts support review, not a numerical correction to sunshine.

Each cloud field requires complete valid daylight samples. A gap means missing or incomplete cloud, never clear sky. Missing rain or one cloud layer does not erase the others. Cloud forecasts can extend beyond sunshine forecasts; such dates are marked “cloud only” when a single model is selected. Hourly source fields · Cloud calculation and limitations.

Source checks and cloud / rain context

Only missing sunshine/radiation inputs or physical inconsistencies suppress a sunshine amount. Total, low, medium and high cloud are checked independently and used as daylight context for all four models. Extensive total or low/medium cloud alongside high sunshine prompts advisory review, not suppression. High-cloud amounts help interpret those flags, but do not establish optical thickness. The thresholds are uncalibrated and not probabilities or verified errors.

Cloud means integrate hourly endpoints over the actual daylight interval, including partial sunrise/sunset hours. They do not establish that the daily-mean cloud and sunshine occurred simultaneously. Rain covers whole intervals that overlap daylight. The provider column retains the original sunshine estimate for diagnosis, including failed inputs; it is not a corrected forecast. Source investigation: why reliable replacement totals are still unavailable

The remaining problem is the source and sunshine calculation. Mean radiation cannot tell us how many minutes direct sunlight exceeded the bright-sunshine threshold. Neither a daylight cap nor arbitrary cloud/rain thresholds can recover that missing information. These displayed estimates therefore remain provisional.

ECMWF IFS: the native sunshine-duration field (sund) is absent from the listed public download subset. Wider forecast access requires an appropriate service agreement or provider. The current IFS radiation feed also contains confirmed inconsistencies; those values remain excluded.

GFS: NOAA publishes SUNSD, and actual GRIB records were retrieved. However, the inspected physics code uses total downwelling shortwave radiation in its sunshine diagnostic. Its files also label the duration as instantaneous. This needs an operational definition and accumulation-period check before treating it as a comparable direct-beam sunshine forecast.

UKMO Global and UKV: the inspected open-data run inventories have no native sunshine-duration parameter. The separately offered blended probabilistic sunshine product is described by the Met Office as suitable only for technical prototyping; it also cannot provide two separate deterministic model forecasts.

A suitable replacement needs documented sunshine-duration data for each named model/run, or a method independently tested against observed sunshine. No replacement numbers have been invented. Detailed findings and reproducible source checks.

About the data and comparison with ePD

These are experimental radiation-derived estimates from Open-Meteo, not native model sunshine-duration fields. Its approximation ramps from no sunshine at 60 W/m² to full sunshine at 180 W/m² of direct normal irradiance, centred on the 120 W/m² sunshine threshold. Applying this to hourly mean radiation cannot resolve intermittent sunshine and can overstate duration in broken cloud. Hourly API values may be interpolated from longer model intervals.

Each model uses the same 00 UTC forecast cycle. All 24 sunshine intervals must be present at every station before a sunshine day enters the dropdown. At each station, incomplete supporting radiation, invalid units/ranges, material radiation inconsistency, or sunshine outside astronomical daylight withholds the amount. Cloud-only dates are independently labelled. A 2 W/m² tolerance allows radiation rounding noise and a 2-minute tolerance allows solar geometry/refraction differences.

Daylight varies with the exact date and location. Sunrise and sunset are calculated from the full year/month/day and latitude/longitude, including leap years. The station table uses the named station coordinates; model checks and cloud means use the sampled grid coordinates. Both use the same NOAA/Meeus solar equations, standard refraction and a flat sea-level horizon. Twilight is excluded. Hills, obstructions and unusual refraction are not modelled. Sunrise and sunset are in UTC, so clock changes cannot add sunshine. The bound applies to unrounded values: for example, 10.6 hours of sunshine may display as 11 while still fitting a 10h 50m day.

Sunshine values cover 00:00–24:00 UTC. They are rounded once, after summing the day; zero can mean less than half an hour. Cloud percentages cover daylight only. Forecasts are sampled at the nearest model grid cell to each station. Regions are the supplied labels, not regional averages.

These are single forecasts. They do not reproduce ePD’s 10th and 90th percentiles, and disagreement between models is not an equivalent probability range. The estimates have not been calibrated to ePD or validated here against observations. A 500 hPa / pressure chart is useful context but cannot determine a station’s daily sunshine total; AIFS and IFS, and different run times, are distinct forecasts.

The dropdown follows actual complete sunshine or cloud data. ECMWF and GFS usually extend much further than the two Met Office sunshine feeds. Missing or partial days are never counted as zero. The generic “RoI — Republic of Ireland” entry is awaiting a station or averaging definition.

Forecast updates are checked four times daily. The common 00 UTC cycle is used; if today’s cycle is not yet available from every model, the previous day’s cycle is retained. GitHub’s scheduled runs can be delayed.
